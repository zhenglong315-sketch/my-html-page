Concept · 核心概念

四个核心要素，构成整套工作流

先记住这四块，后面所有内容都围绕它们展开。

🤖

Agent 智能体

每个对话里的 AI，承担一个明确角色（编剧、分镜、提示词……），负责具体干活；剪辑等专业环节由人工岗位承担。

🧰

Skill 技能库

预置的专业规范与脚本，告诉 Agent 每个工种"标准做法是什么"，相当于岗位培训手册。

💬

多对话协作

一个工位一个独立对话，上下文干净、输出精准，通过文件系统交接而非记忆。

✅

质量门禁

每道工序完成后必须通过校验，不通过不进入下一步，把问题拦在早期。

六类固定编号：文档之间"传参"用的字段名

这些 SHOT- / IMG- / LOCK- 等前缀不是随便起的代号，而是写进每份文档的"字段名"——给每个镜头、每张图、每把锁一个唯一、固定的编号。

为什么必须这样？因为各个独立对话里的 AI 不共享记忆，不能靠"那个东西"这种模糊说法。它们靠写下编号来传递信息（也就是"传参"）：看到同一个编号，就知道指向的是同一个东西，不会认错、不会传丢。

① 写编号上游文档给每个东西分配唯一编号，如 SHOT-EP001-001
→
② 传编号下游对话只写编号，不复制内容、不靠记忆转述
→
③ 按编号取打开对应文档，凭编号精确找到原内容
SHOT-镜头编号

给每个镜头的唯一编号，是分镜与视频提示词之间互相对账的"主键"，修订时不随意换号。

所在文档：分镜
SHOT-EP001-001（EP001 第 1 个镜头）
MOTION-视频提示词编号

给每段视频生成的提示词编号，与镜头一一对应。《小满食舍》按"生成段落"用 SEG 编号，作用相同。

所在文档：视频提示词
SEG-EP001-01（规范里写作 MOTION-...）
IMG-图片提示词条目

角色/场景/道具的"提示词条目"编号，代表一段可复用的提示词，不等于已经生成的图片。

所在文档：图片提示词
IMG-CHAR-XIAOMAN-SHEET（周小满角色板）
LOCK-连续性锁

锁定跨镜头不能变的事实（服装、道具、发型），执行端逐字带走，防止画着画着就变了。

所在文档：视觉设定 / 图片提示词
LOCK-APRON（深色旧围裙）
REF-参考图槽位

项目里真实存在的图片，写清挂第几张、用途、控制范围，让模型按槽位正确使用参考图。

所在文档：图片提示词 / 分镜
REF-SHEET-LAYOUT（角色卡版面参考图）
PLAN-挂图计划（备用）

图片在项目外、由创作者自己在生成界面挂载时使用，只声明"该挂什么"，不谎称文件已存在。本项目实际用 REF，未触发。

所在文档：分镜（备用）
PLAN-SHOT-START（规范命名示例）

Preparation · 准备

开工前，一次问清这 8 项

信息越明确，后面返工越少。这 8 项是初始化的输入，缺哪项就先确认哪项。

序号确认项说明 / 示例
1故事点子一句话核心设定，如"25 岁孙女守爷爷留下的老食堂"
2题材类型决定爽点与情绪节奏，如都市温情、家庭、逆袭
3集数 × 时长如 15 集 × 90 秒，无合理默认，必须确认
4画幅竖屏短剧统一 9:16
5视觉风格如 urban_warm 都市温情写实电影感
6说明语言创作者可读说明用中文
7提示词语言图片/视频提示词用英文，更适配主流模型
8项目路径明确存放目录，所有文件都在项目内交接
Structure · 目录结构

一套规范目录，五份文档是唯一真相

每集按需维护五份 Markdown，不再另建平行的结构化数据；没有内容时不预建空文件。

新短剧项目/ ├─ short-drama.json # 项目配置（集数/时长/画幅/模型档案） ├─ 项目开发/ # 可选：简报、故事引擎、分集地图 ├─ 剧集/ │ └─ EP001/ │ ├─ 剧本.md # ① 编剧 │ ├─ 视觉设定.md # ② 人物/场景/道具/连续性锁 │ ├─ 分镜.md # ③ 镜头 + 冻结关键帧 │ ├─ 图片提示词.md # ④ 角色/场景/道具板 │ ├─ 视频提示词.md # ⑤ 与镜头一一对应 │ └─ 制作成果/ # 生成的图片、视频素材 └─ 复盘沉淀/ # 项目结束后的方法论沉淀

五份文档对应 5 个工位

剧本、视觉、分镜、图片提示词、视频提示词，各自落盘，跨文档通过稳定 ID 引用。

剪辑单在素材生产后

剪辑师根据真实素材记录取舍、入出点、声音与字幕，不参与上游故事创作。

Init · 初始化

一条命令初始化，确定参数一次带上

已经确认的事实（集数、时长、画幅、语言）在 init 时就写进配置，不要留空以后再补。

python3 project_tool.py init ./小满食舍 \ --title "小满食舍" \ --language zh --prompt-language en \ --aspect-ratio 9:16 \ --episode-count 15 --target-seconds 90

① 只建配置和空目录

init 不预建空文件，第一次创作时才把文档写进对应集目录。

② 状态只有两种

生产档案只有 unset（未决定）与 accepted（已接受），不造中间状态。

③ 用 status 复核

初始化后运行 status，确认配置与后续模型档案都正确写入。

Stations · 九工位实操

点击展开每个工位，照着做

每个工位卡片都可点击展开/收起，内含职责、调用 Skill、操作步骤、《小满食舍》真实实例。绿色卡片为人工岗位。

1

故事开发

调用 Skill：short-drama-develop · 产出：创作简报 / 故事引擎 / 分集地图
▾
核心职责
把一个点子发展成能持续制造选择、代价与状态变化的故事系统，确定系列承诺、爽点节奏与分集边界。
操作步骤
  • 明确题材与观看承诺，确定主角想要什么、阻力是什么。
  • 搭故事引擎：核心冲突、人物关系、每集固定结构。
  • 做分集地图，规划每集的钩子、转折、回报与集间交接。
《小满食舍》实例

规划为 15 集 × 90 秒。主角周小满（25 岁）守爷爷留下的老食堂，分集地图锁定每集"3 秒钩子 + 情绪转折 + 结尾悬念"，并在 episode-map.jsonl 中固化每集边界。

2

编剧

调用 Skill：short-drama-write · 产出：剧本.md
▾
核心职责
把分集意图写成可表演、可拍摄、会改变故事状态的剧本，一级标题以集号开头，场次用固定格式。
专用标签
[VO] 画外音 · [OS] 画外对白 · [SFX] 声音 · [画面文字] · [连续性] · [转场]；对白写"角色（表演提示）：台词"。
操作步骤
  • 读取本集进入状态、目标、转折与退出状态。
  • 逐场写，每场都要改变信息、关系或情绪，无变化的场删掉。
  • 反查因果、台词去 AI 味，不靠解释代替行动。
《小满食舍》实例

EP001 共 3 场，结尾画外音："爷爷走了。可火还热，锅还在。我也还在。"一句话立住人物与全剧基调，动作叙述与对白严格区分，不混写。

3

视觉设定

调用 Skill：short-drama-assets · 产出：视觉设定.md
▾
核心职责
从剧本拆出人物、造型、地点、道具，写识别锚点与连续性锁，不抢写剧情和镜头走位。
三个区分
身份（换了就不是同一人/物）· 变体（身份不变但服装/状态改变）· 镜头瞬态（姿势视线，归分镜）。
操作步骤
  • 逐场找实体与可见描述，先不创建资产。
  • 对每项决定新建、复用、变体或标记未决，含混不猜。
  • 对跨镜不变的服装/道具/发型写 LOCK 锁，锁面用提示词语言逐字写。
《小满食舍》实例

EP001 写了 5 把连续性锁：LOCK-APRON（旧深色围裙）、LOCK-KETTLE（灶上水壶）、LOCK-RATTAN-CHAIR（旧藤椅）、LOCK-GARLIC（剥了一半的蒜）、LOCK-NOTEBOOK（贴胶带的旧笔记本），确保跨镜一致。

4

图片提示词

调用 Skill：short-drama-image-prompts · 产出：图片提示词.md
▾
核心职责
把视觉事实写成可直接投产的角色板、场景板、道具板，每项用 IMG 编号，正文放在"可复制提示词"块。
编译顺序
主体与身份锚点 → 当前变体 → 构图/视角 → 光色/材质 → 背景边界 → 禁止项。
操作要点
  • 角色卡必须挂头肩特写 + 全身三视图，人脸才能稳定。
  • 换造型时生成新的造型角色卡，不拿单人造型板当角色卡。
  • 每张参考图写清用途与控制范围，不写"全参考"。
《小满食舍》实例

角色卡为左侧头肩特写 + 右侧全身三视图，约 7 头身、肩颈修长、身形挺拔，使用模型 seedream 5.0 pro；全身遵循真实人体比例，禁止五五开或矮化。

5

分镜

调用 Skill：short-drama-storyboard · 产出：分镜.md
▾
核心职责
把剧本和视觉事实转成有镜头职责、空间连续性和冻结关键帧的分镜，每镜一个 SHOT 编号，含起幅、唯一动作、终点。
硬规则
单镜时长不超过 15 秒（含 15 秒），分镜时长要在模型原生时长范围内；先分析空间几何再执行，不机械照搬。
操作步骤
  • 读取模型原生时长，自检上一段结束的机位、朝向、站位。
  • 逐镜设计景别、机位角度、起幅、唯一动作与终点。
  • 写冻结关键帧，再回填图片提示词项、参考图、视觉依据三类依据。
《小满食舍》实例

SHOT-EP001-001"门外停步"写清起点（手悬门把）→ 触发（玻璃落地声）→ 终点（手收回、视线转向门缝），视觉依据逐字回填人物与地点，机位角度单独标注，不沿用母版默认机位。

6

视频提示词

调用 Skill：short-drama-video-prompts · 产出：视频提示词.md
▾
核心职责
把已确认镜头和起始帧写成与 SHOT 一一对应的 MOTION 提示词，描述运动链、表演、运镜、声音，可直接复制。

有真实 REF 或 PLAN 时走图生视频，原样携带参考槽位、顺序、用途与控制范围，正文只重述运动所需的局部起点和防漂移事实。

只有创作者明确选择文生时才走此路径，正文必须自足包含人物、造型、地点、构图、光线等静态视觉锚点，不能用"保持已有外观"代替模型没收到的图。

关键红线
普通的"无参考图"表示待补，不是文生授权；"待补"会阻止最终视频提示词，必须先刷新参考绑定。
《小满食舍》实例

每个 MOTION 与 SHOT 对应，引用的中文（如台词）都能在剧本或视觉设定里找到原字；正文明确"不生成非画内字幕/对白文字叠加"，让对白只通过声音和口型发生。

7

生产执行

调用 Skill：short-drama-produce · 产出：制作成果/ 下的图片与视频
▾
核心职责
在创作者明确确认后，把已写好的生产规格安全送到 adapter，执行图片、视频、TTS 或音乐生产并落回项目。
硬闸门（不可合并）
  • prepare：建立有边界的 job，展示完整预览（数量、提示词、参考绑定、输出）。
  • 确认：创作者看到预览后明确同意，"继续/预算没问题"不算确认。
  • run：执行生产，成功或失败后再次执行都要重新确认。
边界
不代替创作者填写确认；job 的 source 指向拥有提示词的 Markdown，输出写到对应集的制作成果目录。
《小满食舍》实例

图片 job 用图片提示词.md 的 IMG 选择器取首帧，视频 job 用视频提示词.md 的 MOTION；本地参考图按 base64 直接送出，PLAN 类（图在项目外）无法进入生产，需先放进项目改成 REF。

8

人工剪辑（关键岗位）

由剪辑师手动完成 · 工具：剪映 / Premiere Pro / After Effects / Audition · 产出：剪辑单.md 与成片
▾
核心职责
剪辑是人工二度创作，把逐镜素材装配成成片，决定叙事节奏与观感；配音、字幕、音效、特效、转场、调色全部由剪辑师手动完成，不调用 AI 自动剪辑。
剪辑流程

① 素材整理

分类归档、规范命名、备份，挑双镜头、剔除废卡。

② 粗剪

按分镜顺序拼接，确认故事成立、逻辑通顺。

③ 精剪

逐帧精修，修正衔接、消除穿帮，切点精准。

④ 节奏卡点

强化 3 秒钩子、反转与情绪节点，贴合观看习惯。

声音与画面包装

人声 / 配音

逐镜核对音画同步、口型，做降噪，按情绪匹配语气。

字幕包装

黑体/圆体、白字黑边、下方不挡脸，校对错别字。

音效 / BGM

按节奏卡点，音量低于人声，环境音摆脱塑料感。

转场

硬切为主，情绪转折用淡入淡出，不用花哨转场。

特效 / 包装

加简单特效、字幕动画、片头片尾与 Logo，统一风格。

调色 / 导出

统一色调、降噪，按 1080P、9:16、MP4 导出。

权责边界
删镜、缩镜、调顺序、做包装属于剪辑师的取舍；但改台词、改镜头职责、改故事，要回到对应上游工位，不能在剪辑台上擅自改写。
《小满食舍》实例 · 音量平衡（专业参数）

三层音轨手工平衡：人声约 -6dB、背景音乐约 -18dB、环境音约 -24dB；暖黄灶火与清晨灰白的色调调色统一，最终成片输出到"制作成果/成片/"。

Handoff · 多对话传参

一个工位一个对话，靠文件交接

每个独立对话只专注一个职责，上下文干净；不靠记忆转述，而是读上游落盘文件，通过稳定 ID 引用。

上游产物交给下游交接方式
分集地图编剧读本集进入状态、目标、转折，写剧本.md
剧本.md视觉设定 / 分镜拆实体、设计镜头，引用场次号
视觉设定.md图片/视频提示词按 LOCK 锁面逐字带走，视觉依据回填
图片提示词.md分镜 / 生产用 IMG 编号查找，生产取首帧
分镜.md视频提示词每个 MOTION 对应一个 SHOT
视频提示词.md生产执行用 MOTION 选择器，参考绑定一起送
制作成果/素材剪辑师（人工）读真实文件，按剧本分镜核对叙事

原则一：单职责

一个对话只做一个工位，避免上下文混杂导致输出漂移。

原则二：先读再做

新对话先读上游文件，不凭记忆和想象补事实。

原则三：文件为准

所有交接以落盘文档为权威，口头和记忆不作数。

Quality Gate · 质量门禁

两类脚本，把错误拦在投产之前

跨文档结构校验

python3 creator_markdown_check.py \ 剧集/EP001 --project-root .

机械核对画面代称、视觉依据、连续性锁、REF/PLAN、ID 引用是否一致。

视频提示词静态回归

python3 视频提示词质量门.py \ <提示词文件.md> --total 90

通过标准：全部检查 ERROR 数 = 0，WARNING 仅提示。

Red Lines · 红线避坑

不靠记忆假设

新对话先读上游文件，不凭记忆和想象补事实。

不把"无参考图"当文生授权

普通"无"表示待补，只有明确选择才走文生。

不绕质量门强行续跑

校验不过就停下修正，通过后再进下一阶段。

单镜不超过 15 秒

不替创作者确认生产

"继续/预算没问题"不算确认，不得代填。

不擅自加台词/改设定

引用的中文必须能在剧本或视觉设定里找到原字。

Comparison · 横向对位

从"实拍剧组"到"智能协作"

传统真人短剧

  • 40~60 人剧组，劳动密集
  • 量产 20~40 天，精品 2~4 个月
  • 普通成本 30~40 万，精品可达数百万
  • 实拍 7~15 天，日均 14~16 小时
  • 资产一次性消耗，重拍成本高

AI 智能协作

  • 3~8 人（核心 3 人：导演/抽卡师/后期），含人工剪辑
  • 数天周期，无需实拍现场
  • 主要为算力成本，视频生成约 1~1.2 元/秒
  • 无现场高强度作业，约半数镜头需抽卡
  • 资产可复用、可批量、可沉淀

数据来源：澎湃新闻、人民日报、人民网等公开报道（2025-2026）。AI 并非取代所有人，而是把人从重复劳动中解放，聚焦创意、决策与人工剪辑等关键环节。
